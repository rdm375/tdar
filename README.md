# TDAR

**Taylor-Disagreement Adaptive Refinement** is a derivative-informed adaptive sampling method for expensive smooth scalar functions on a two-dimensional domain. TDAR uses local first-order Taylor models to identify unresolved structure, then concentrates new evaluations where those local models disagree.

![TDAR refining the curved-ridge example](docs/assets/curved-ridge.gif)

The animation is generated by the public library API in `examples/visualization/animate_curved_ridge.py`; it is not a hand-built illustration.

## Quick start

```python
import jax.numpy as jnp
from tdar import farthest_point, sample


def expensive_function(x):
    return jnp.sin(6.0 * x[0]) * jnp.exp(-3.0 * (x[1] - 0.4)**2)


result = sample(expensive_function, farthest_point(16), budget=80)
X, y = result.x, result.y
```

`X` contains the selected sample locations and `y` contains the corresponding function values. Gradients used internally for refinement are also available as `result.gradients`.

## What TDAR does

TDAR uses automatic-differentiation gradients only to decide **where to sample**. It does not prescribe a downstream surrogate model. The returned design can therefore be used with SciPy, scikit-learn, JAX, PyTorch, a table builder, or a project-specific surrogate.

Each refinement batch combines Taylor-model disagreement in Delaunay triangles and on convex-hull edges, a unified triangle/boundary priority queue, scale-aware boundary closure, local maximin point placement, and deterministic global farthest-point filling when an adaptive batch cannot be filled.

## Examples

The repository keeps a small set of research problems because they illuminate different behavior rather than because TDAR depends on them:

- `examples/curved_ridge.py` — a narrow curved transition; the primary geometric demonstration.
- `examples/quadratic.py` — a smooth, globally well-behaved reference problem.
- `examples/multiscale.py` — broad structure plus a small localized feature.
- `examples/custom_function.py` — the minimal user-defined-function workflow.

The problem definitions live under `examples/problems/`, outside the installable `tdar` package.

## Recording refinement history

Normal runs do not retain triangulations or refinement decisions. Visualization and diagnostics can opt in:

```python
from tdar import TDARConfig, farthest_point, sample

result = sample(
    expensive_function,
    farthest_point(16),
    budget=128,
    config=TDARConfig(record_history=True),
)

for step in result.history:
    print(step.points.shape, step.proposed_points)
```

Each `TDARStep` records the pre-batch points and triangulation, boundary edges, triangle and boundary indicators, proposed points, and whether each accepted proposal came from a triangle, boundary edge, or global fill. History is opt-in so production sampling does not pay the storage cost.

## Scope

TDAR method v1 is intentionally narrow: scalar functions, two independent variables, the unit-square domain, first derivatives available through JAX, and Delaunay geometry. General domains, vector-valued functions, higher dimensions, and alternate derivative providers are future API work rather than silently generalized here.

The library chooses evaluation locations; it is deliberately **not** a surrogate-model framework.

## Reproducibility and validation

This package is an extraction of the frozen **TDAR method v1** from the `adaptive-surrogates` research codebase. The production sampler contains no true-error oracle and does not evaluate the target away from accepted sample points. The extracted decision path was checked against the frozen research implementation before library engineering began.

Tests also verify deterministic sampling, exact budget handling, affine fallback behavior, and that enabling history does not alter the selected design.

## Development layout

```text
src/tdar/                 numerical library
examples/                 executable examples
examples/problems/        demonstration functions
examples/visualization/   optional plotting/animation tools
benchmarks/               reproducible baseline comparisons
tests/                    library behavior and regression tests

```

Visualization dependencies are optional (`tdar[viz]`) and do not enter the numerical library's runtime dependency set.

## Status

The algorithm is frozen as **TDAR method v1**. The Python library API is still pre-1.0 and is being exercised as a reusable dependency before its first public release.
